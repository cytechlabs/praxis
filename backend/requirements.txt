# Praxis backend — single clean pinned baseline (PRA-308).
# Every package appears exactly once, pinned. Extras are pinned intentionally on the
# canonical line (python-jose[cryptography], passlib[bcrypt], pydantic[email]) so
# `pip install -r requirements.txt` is deterministic and does not rely on later
# duplicate lines overriding earlier ones.
#
# PRA-321 (Python 3.14 runtime cutover; evaluated in PRA-319, unblocked by PRA-320's
# broker mTLS fix): pydantic is 2.12.0 (pulls pydantic-core 2.41.1, the first line with
# a CPython 3.14 wheel) so the backend runs on the Python 3.14 runtime. That was the
# ONLY web-stack pin change the interpreter move required: uvicorn 0.27.0 /
# pydantic-settings 2.1.0 / httpx 0.26.0 stay on the same lines and are compatible
# (v1-style @validator still works across the whole pydantic 2.x line).
# Everything installs from wheels on 3.14 (no source builds).

# Core
# Starlette parses every form and multipart request, and that parser has carried a
# run of denial-of-service advisories: non-file multipart parts buffered without a
# size bound (CVE-2024-47874, fixed in 0.40.0), the spool-to-disk rollover of a
# large upload run as a blocking write on the event loop (CVE-2025-54121, fixed in
# 0.47.2), and request.form()'s field-count and field-size limits silently ignored
# for application/x-www-form-urlencoded (CVE-2026-54283, fixed in 1.3.1).
# POST /auth/login reaches that parser unauthenticated, and ahead of the route's
# own rate limit, so do not pin starlette below 1.3.1.
#
# 0.137.0 is the smallest fastapi release that both admits starlette 1.3.1 and was
# cut after it shipped. Its declared python-multipart floor is >=0.0.18, which
# keeps the linear Content-Type option-header parser (CVE-2024-24762) in place.
