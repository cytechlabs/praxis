# Database Migration with Alembic

This document provides an overview of how to set up and manage database migrations using Alembic in this project.

## Setup

1. **Alembic Configuration**: The Alembic configuration is located in `backend/alembic.ini`. It specifies the script location and logging configuration.

2. **Environment Configuration**: The `env.py` file in the `backend/alembic` directory configures the database connection using environment variables. `DATABASE_URL` is used when set; otherwise the URL is assembled from the variables below and `POSTGRES_PASSWORD` must be present and non-empty, since no password default exists. Migrations abort with a named error when neither is supplied.
   - `POSTGRES_USER`
   - `POSTGRES_PASSWORD`
   - `POSTGRES_SERVER`
   - `POSTGRES_DB`

## Creating a New Migration

To create a new migration, follow these steps:

1. **Modify Models**: Update or create new models in the `backend/app/db/models.py` file.

2. **Generate Migration**: Run the following command to generate a new migration script:
   ```bash
   docker compose exec backend alembic revision --autogenerate -m "Your migration message"
   ```

3. **Review Migration**: Check the generated migration script in the `backend/alembic/versions` directory and make any necessary adjustments.

## Applying Migrations

To apply migrations and update the database schema, run the following command:
```bash
docker compose exec backend alembic upgrade head
```

## Editing Migrations

If you need to edit an existing migration, locate the script in the `backend/alembic/versions` directory and make the necessary changes. Ensure that the changes are consistent with the current database state.

## Best Practices

- Always review autogenerated migration scripts for accuracy.
- Test migrations in a development environment before applying them in production.
- Keep migration messages descriptive to understand the changes made.
